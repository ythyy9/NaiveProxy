# 代理配置演变时间线

> 时间主要来自本地文件修改时间和嵌套仓库 Git 历史。文件修改时间不等于服务器实际切换时间，以下更适合作为“相对演变顺序”。[Source: 本地文件系统与 hk-traffic-monitor Git 历史, 2026-07-18]

## 2026-06-15：美国家宽直连与香港中转对照

- `sing-box-us-reality.json` 建立早期基线：客户端通过香港侧入口访问美国落地，使用 Vision、严格路由和直连 UDP DNS。[Source: 对应配置, 2026-06-15]
- `sing-box-us-reality-direct-debug.json` 使用同一美国端接入材料改做直接连接，并把日志改为 debug，像是用于排除香港中转问题的直连对照。[Source: 两文件结构比较, 2026-06-15；用途为推断]

## 2026-06-16：香港手机节点的 DNS / UDP / flow 实验

这个阶段围绕同一香港节点连续产生多个近似版本，核心目标是排查手机端 TUN、DNS 和 UDP 兼容性。[Source: `sing-box-hk-vless-phone*` 文件族结构与时间, 2026-06-16；目标为推断]

演变顺序大致是：

1. `phone`：Vision + 严格路由 + 直连 UDP DNS。
2. `dnsfix`：DNS 改为 TCP 经代理，关闭严格路由。
3. `dnsroute`：增加专用 DNS 出站、53 端口路由并阻断 UDP。
4. `113plus`：改用较新的 DNS 劫持/拒绝动作写法。
5. `noflow-113plus`：去掉 Vision flow，并换用另一组用户材料。
6. `doh-direct` / `localdns` / `doh-nodetour`：对比直连 DoH、本机 DNS 和无显式 detour 的 DoH。

[Source: compiled from `private-configs/02-hk-phone-dns-tests/` 配置差异, 2026-06-16]

## 2026-06-20：香港新入口

`sing-box-hk-new-phone-9444.json` 延续“无 flow + DNS 劫持”的方向，但换了一整组入口参数，像是在 x-ui 中新建或迁移了入站。[Source: 配置字段指纹比较, 2026-06-20；x-ui 迁移为推断]

- 建立 `hk-traffic-monitor`：vnStat 读取网卡流量，脚本生成 JSON 并推送到 GitHub，静态页面展示用量。[Source: hk-traffic-monitor 初始提交与 README, 2026-06-27]
- 随后修复脚本数据读取，并发生 5 次短间隔自动流量提交，说明当时做过实际部署测试。[Source: hk-traffic-monitor Git 历史, 2026-06-27]

## 2026-07-28：v2rayN/Xray 实机核验与 Mux 优化

- Windows 客户端已实机确认为 v2rayN 7.22.7 + Xray 26.6.1 TUN；活动入口仍属于日本入口谱系，最终出口仍为美国住宅 IP。六个独立出口查询服务一致返回同一美国 IP。[Source: live process、生成配置与出口查询, 2026-07-28]
- 当前路由只让私网直连，所有公网端口由 catch-all 规则进入代理；没有 `geoip:cn`、`geosite:cn` 或其他中国公网直连规则。[Source: v2rayN `binConfigs/config.json`, 2026-07-28]
- 公共 DNS 使用 Cloudflare DoH 并经代理出站；`xray_tun` 与物理网卡均由持久化任务维持 `1.1.1.1 / 1.0.0.1`。重启后的任务结果为 `0x0`。[Source: 生成配置、Windows DNS 状态与计划任务, 2026-07-28]
- 原配置关闭 Xray Mux。五个不同域名并行冷请求的基线为 33/40 成功，成功请求单站中位数约 1860–2371 ms；隔离 A/B 显示 `Mux concurrency=8` 可显著减少重复 Reality/TCP 建连。正式启用后 curl 复测为 40/40 成功、整体中位数 1122 ms；Edge 按 CleanIP 的 `no-cors/no-store` 方法复现为 39/40 成功、整体中位数 240 ms，首轮之后 35/35 成功；固定 4.17 MiB 下载 3/3 成功、平均 7.34 Mbps。[Source: local A/B benchmark, 2026-07-28]
- 正式配置只修改活动 Profile 的 `MuxEnabled`；TUN MTU 仍为 9000，未把两个变量同时修改。回退备份为 v2rayN `guiConfigs` 下的 `guiNDB.db.bak-mux8-20260728-040644`。[Source: SQLite semantic diff、完整性检查与备份哈希, 2026-07-28]
- 美国侧 `8443` 与历史直连配置及 x-ui 截图相符，基本确认为 VLESS + Reality 直连/备用入站；`22` 实时返回 Debian OpenSSH banner，本机 `known_hosts` 有该 IP 的历史记录，PowerShell 历史中另有 16 次对该 IP 默认端口的交互式 SSH 命令，因此可以高置信度视为用户使用过的美国侧管理入口，不应在未登录核对监听进程与 NAT 前关闭。[Source: local config、User screenshot、TCP banner、known_hosts 与 redacted command-history count, 2026-07-28]
- CleanIP 的 `Via: 2.0 Caddy` / `X-Forwarded-For` 提示来自其自身 Cloudflare/Caddy 请求链，对照远端访问也会出现，不作为客户端代理泄漏处理。本轮按用户要求未验证 Claude/Gemini 可达性。[Source: CleanIP headers endpoint 与 remote-fetch control, 2026-07-28]
