# 服务器资料安全与恢复边界

## 风险结论

16 份 sing-box 文件都包含能组合成完整客户端接入配置的端点、UUID 和 Reality 参数；旧文件是否已经失效无法判断，因此全部按“可能仍有效”处理。[Source: 本地敏感字段审计, 2026-07-18]

未发现 Reality 服务端私钥、x-ui 管理密码/API token、SSH 私钥/密码、订阅链接、x-ui 数据库或 SQLite 备份。[Source: 本地敏感字段审计, 2026-07-18]

Reality 公钥单独看不是秘密，风险来自它与端点、UUID、short ID 等组合后形成可用配置。[Source: 本地配置组合风险审计, 2026-07-18]

## 目前采取的保护

- 原始配置集中到 `private-configs/`，与脱敏文档分开。[Source: 本次整理, 2026-07-18]
- 根 `.gitignore` 忽略该目录中的 JSON、备份、数据库和常见密钥文件，降低在父级仓库中误提交的风险。[Source: 本目录 .gitignore, 2026-07-18]
- 文档只描述角色、演变和字段行为，不复制原始 IP、UUID、密钥或完整端点。[Source: 本次整理规范, 2026-07-18]

这些措施 **不等于加密**，也不阻止 Obsidian Sync、网盘、系统备份或其他同步软件读取文件。[Source: 本次整理设计边界, 2026-07-18]

## 建议的最终保管方式

1. 把仍需保留的原始配置迁到知识库之外的加密目录或密码库附件中；知识库只留文件用途、日期和密码库记录名。
2. 登录 x-ui 核对历史入站，把不用的 UUID/用户标记为 revoked 并实际停用。
3. 如果这些文件曾被公开、同步到不可信位置或发给他人，轮换仍在用的 UUID；是否同时调整 short ID 由实际暴露范围决定。
4. x-ui 服务端备份单独加密；不要把明文数据库放回此目录。
5. 删除任何明文备份前，先验证加密备份可恢复。

[Source: compiled from 本地敏感字段审计与当前恢复缺口, 2026-07-18]

## 为什么目前不能完整恢复

客户端配置只告诉我们“客户端如何进入第一跳”。完整恢复“日本软银中转 → 美国家宽落地”至少还需要：

- x-ui 版本、安装节点及可验证的面板/数据库备份。
- 日本端服务端入站、美国端出口和两端之间的第二跳配置。
- 防火墙、路由、系统服务、DNS 和证书/Reality 服务端材料。
- 服务器提供商、续费、流量和 IP 变更资料。
- SSH 与密码库记录的引用。

[Source: 本地文件缺口审计, 2026-07-18]

## `hk-traffic-monitor` 的单独风险

- 项目文件中未发现内嵌 token 或私钥，但流量快照会暴露节点角色、配额、接口名和使用时间。[Source: hk-traffic-monitor 内容与 Git 历史审计, 2026-07-18]
- README 指导使用 `credential.helper store`，这可能在 VPS 上明文保存 Git 凭据；如果项目仍启用，应改用范围受限的 deploy key、细粒度 token 或安全凭据助手。[Source: hk-traffic-monitor/README.md, 2026-06-27]
- 自动脚本会持续提交流量历史；若仓库是公开的，应确认这类运营信息可以公开。[Source: hk-traffic-monitor/scripts/update-traffic.sh, 2026-06-27]
