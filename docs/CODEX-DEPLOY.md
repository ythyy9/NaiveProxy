# 给 Codex 的执行任务书

可以把下面这段话连同仓库地址交给 Codex：

> 请读取 https://github.com/ythyy9/NaiveProxy 的 AGENTS.md 和部署文档，在我授权的 VPS 上完成实际部署。每个客户端一个独立 HTTPS 订阅链接，每个链接包含四个节点：Naive 直出、Naive 家宽、HY2 直出、HY2 家宽；HY2 要有 Salamander 混淆和端口跳跃。完成网站、证书自动续期、开机启动、订阅更新、账号撤销和回退，并从客户端网络逐条测试。先查看已有连接和配置，只向我询问确实缺少的登录、客户端与家宽信息；不要把任何真实凭据提交到 GitHub。

## 开始前查清

| 输入 | 如何确定 |
| --- | --- |
| VPS 与 SSH | 优先使用已有授权会话；没有则通过安全方式获取登录信息，不要求把密码写到公开聊天 |
| 系统与端口 | 核实 Linux x86_64、systemd、可用 TCP 80/443；盘点已有服务和 NAT 规则 |
| 客户端 | 确认软件、版本、数量和名称；默认可用 `friend1`…`friend5`，数量按用户实际需求 |
| 证书身份 | 有域名使用对应域名；没有域名使用 VPS 的公网 IPv4 |
| 家宽出口 | 使用真实自有/已授权上游，核实连接方式、认证、出口 IP 和可用协议 |

“一个客户端”在这里是一份独立凭据/订阅记录，不是硬件绑定。用户分享链接后别人也能使用；本套件不实现一机一号、设备数限制、计费额度或自动到期。

## 执行顺序

1. 记录相关服务与端口现状，选择空闲端口范围。默认直出 UDP 28000–28031、家宽 UDP 28100–28131；只开放所需入口，保留 SSH。
2. 按[家宽准备](optional-routes.md)配置带认证、仅绑定 `127.0.0.1` 的 SOCKS5 桥，先核对它的真实出口。将 VPS 到远程家宽这一段的传输方式说明白。
3. 按[安装教程](installation.md)申请 IP 或域名证书，生成 schema 2 设置；填写已验证的 `residential_upstream` 后 render。不要把占位地址当成真实出口。
4. 安装 Naive 与两个 HY2 实例。Hysteria 内置端口范围会创建自己的重定向规则；不要再叠加旧文档中的手动 NAT 规则，也不要清空防火墙。
5. 配置生成的每个客户端目录只有一个 `subscription-url.txt`。HTTPS 订阅响应是四行节点 URI 的 Base64，不能要求用户手动维护四份订阅。
6. 通过下表验收后，按客户端分别交付。若某项因实际网络或权限无法完成，保留结果与下一步，不宣称已全部部署成功。

## 完成证据

| 检查 | 通过条件 |
| --- | --- |
| 订阅可达 | 从客户端网络通过有效 TLS 获取；每个有效链接解码恰好四行，错误令牌返回 404 |
| 账号隔离 | 每个人的链接和四套认证独立，响应内没有其他人的节点 |
| 客户端导入 | 在目标软件中更新一次订阅，显示四个可选择节点；HY2 的端口范围与 Salamander 参数没有丢失 |
| 四条实际连接 | 逐个发起实际请求，Naive/HY2 直出为 VPS 出口，Naive/HY2 家宽为同一授权家宽出口 |
| 认证 | 错误密码不能代理；未经认证访问仍是普通网站 |
| HY2 跳跃 | 持续请求并观察至少两个不同入口 UDP 端口，不只检查配置字符串 |
| 家宽故障 | 停止自己新增的桥后家宽节点失败，直出仍可用；恢复桥，不留下故障状态 |
| 撤销与更新 | 使用临时测试客户端验证停用后旧订阅失效、旧认证和旧会话终止；恢复或删掉临时记录 |
| 续期 | Certbot dry-run 与 deploy hook 通过，服务加载对应证书；HY2 新握手仍验证证书 |
| 运行与回退 | 三个代理服务及续期 timer 启用；说明停止范围和上一配置的恢复入口 |

已有生产服务时，重启整台 VPS 不是默认验收步骤。按必要性验证本次新增服务的启用与恢复即可。

## 交付格式

给每个人自己的一个链接，列出四个节点名称和使用方式；给管理员额外提供私有账号文件位置、版本、服务名、续期与回退命令。凭据通过用户认可的私有渠道交付，不能放在公开 Issue、PR、日志或静态网站里。
